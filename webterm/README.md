# AirTTY 網頁藍牙終端

**免安裝、免配對的瀏覽器 BLE 終端。**

👉 **[開啟網頁終端](https://airtty.github.io/webterm/)**

開頁 → 按「選擇裝置並連線」→ 從瀏覽器跳出的清單選你的 AirTTY → 輸入連線密碼 → 進 console。
不必切換 WiFi、不必安裝任何軟體、不必在系統裡先配對藍牙。

適合的情境：筆電正連著公司網路要一邊查資料、現場 WiFi 訊號很吵、或單純懶得換網路。

**手機也能好好操作** —— 內建快捷鍵列補上手機沒有的 Tab／Esc／Ctrl／方向鍵，
另有貼上、字級調整與連線紀錄下載。詳見下方「[快捷鍵列與工具列](#快捷鍵列與工具列)」。

## 快捷鍵列與工具列

手機沒有 Tab／Esc／Ctrl／方向鍵 —— 這是在行動裝置上操作 console 最大的痛點。
按標題列右側的 **⌨ 快捷鍵** 可展開／收合這排按鈕
（**手機預設展開**、桌機預設收起，你按過之後就記住你的選擇）。

### 按鍵（每一顆都是按一下就送出）

| 按鈕 | 送出（16 進位） | 用途 |
| --- | --- | --- |
| `Tab` | `09` | 指令補全 —— 網管最常按的一顆 |
| `Esc` | `1B` | 離開目前的提示／選單 |
| `?` | `3F` | Cisco 式的情境說明（context help） |
| `⏎` | `0D` | Enter（CR） |
| `Ctrl+C` | `03` | 中斷目前指令 |
| `Ctrl+Z` | `1A` | 回到特權模式／暫停前景工作 |
| `Ctrl+^` | `1E` | 即 **Ctrl+Shift+6** —— Cisco 用來中斷 `ping`／`traceroute`／`telnet` |
| `Ctrl+A` | `01` | 游標移到行首 |
| `Ctrl+D` | `04` | 刪除游標處字元／結束輸入（EOF） |
| `Ctrl+U` | `15` | 清掉整行重打 |
| `Ctrl+W` | `17` | 刪掉前一個單字 |
| `↑` | `1B 5B 41` | 上一筆歷史指令 |
| `↓` | `1B 5B 42` | 下一筆歷史指令 |
| `←` | `1B 5B 44` | 游標左移 |
| `→` | `1B 5B 43` | 游標右移 |
| `Break` | （不是位元組，見下方） | 送出序列 Break。**需裝置韌體 v1.8 以上**；更舊的韌體上這顆會整顆隱藏 |
| `Ctrl+…` | （不送位元組） | 進階備援，見下方 |

方向鍵送的是標準 CSI 序列（`ESC [ A/B/C/D`），Cisco IOS、Juniper Junos、Linux
的 readline 都吃這一組。`Ctrl+A`／`Ctrl+U`／`Ctrl+W` 是 console 行編輯最常用的三顆，
Cisco IOS、Junos 與 bash readline 通用。

**按鈕不會因為未連線而變成按不動** —— 未連線時按下去會跳出「尚未連線」提示浮條，
而不是靜靜地沒反應（分不出是「沒點到」還是「沒連線」很惱人）。每次點擊都有按壓閃爍回饋。

### Ctrl+…：進階備援（罕用組合才需要）

常用組合上表都給了獨立按鈕，正常操作用不到這顆。要送出上表沒有的組合
（例如 `Ctrl+X`、`Ctrl+R`）時：

1. 按一下快捷鍵列**最後一顆** **Ctrl+…** —— 按鈕變橘色並跳出「請再敲一個鍵」。
2. 從鍵盤（手機就是軟體鍵盤）敲下要組合的那個字元。
3. 該字元會以 Ctrl 組合送出，狀態自動解除。

對照規則是 ASCII 的標準做法（把字元碼的高位清掉，`& 0x1F`），另外補上幾個常用的：

| 你敲的鍵 | 實際送出 | | 你敲的鍵 | 實際送出 |
| --- | --- | --- | --- | --- |
| `A`–`Z`（大小寫皆可） | `01`–`1A` | | `?` | `7F`（DEL） |
| `[` `\` `]` `^` `_` | `1B`–`1F` | | 空白 或 `2` | `00`（NUL） |
| `6` | `1E`（同 `Ctrl+^`） | | `3` `4` `5` `7` | `1B` `1C` `1D` `1F` |

- 再按一次 **Ctrl+…** 可以取消等待。
- 等待中若改按其他直點按鍵（例如 Tab），該鍵會照原樣送出，Ctrl 等待狀態同時解除。

### Break 鍵與線路控制（**韌體 v1.8 起支援**）

serial break 是**線路狀態訊號**（把 TX 線拉低超過一個字元時間），**不是一個字元**，
所以沒辦法用「送某幾個位元組」達成 —— 換鮑率、DTR／RTS 同理。

**韌體 v1.8 起**裝置端多了一條**獨立的控制通道**（與序列資料完全分流），
這一頁因此能做到：

| 功能 | 在哪裡 |
| --- | --- |
| ⚡ **送 Break** | 快捷鍵列的 `Break` 鍵，或 **⚙ 線路**面板。拉低 250 毫秒再放開，**由裝置端計時**。**送出前會先跳確認**，原因見下 |
| **換鮑率** | 亂碼提示下方的「一鍵試鮑率」，或 **⚙ 線路**面板自己填 |
| **資料位元／同位／停止位元** | **⚙ 線路**面板 |
| **DTR／RTS** | **⚙ 線路**面板 |
| **modem 狀態燈**（DCD／CTS／DSR／RI） | **⚙ 線路**面板標題列，由設備回報驅動 |

**韌體比 v1.8 舊的話**：這些按鈕**整組不會出現**（`Break` 鍵也隱藏）——
刻意不做成按了沒反應的假按鈕。那種情況下要送 Break 或改鮑率，走這兩條路：

- 連上 AirTTY 的 WiFi → 開管理介面的**網頁終端**，那裡有 Break 按鈕與鮑率下拉。
- 用支援 **RFC 2217** 的軟體（PuTTY 的 telnet com-port、pyserial 的 `rfc2217://`、
  各家 VSP 虛擬序列埠工具）連 `<裝置 IP>:4001`。

#### ⚠️ 為什麼 Break 要先確認

serial break 不是一般按鍵，是給「開機時中斷、進 ROM monitor」用的訊號，
**後果可能不可逆**。實測一台 **FortiGate-60F**：送出 Break 之後 console 直接進入
Linux 的 **SysRq 模式**，畫面列出 `reBoot`（立刻重開）、`Crash`（故意當機）等選項
—— 此時**你敲的下一個鍵**就可能把這台正式設備弄掛。

所以這顆鈕與「多行貼上」採同一條紀律：**會對正式設備造成不可逆後果的動作，一律先問**。
送出後請**先看清楚畫面再打字**。換鮑率不需要確認（頂多看不到字，改回來就好）。

#### 「按了卻說沒生效」是什麼意思

同一台 AirTTY 同時**只有一位使用者有寫入權**（先連上的那位），其他人唯讀。
唯讀時這些設定送得出去、但裝置端不會套用，畫面會明講
「**送出了但沒有生效 —— 可能另一位使用者持有寫入權**」。

這是刻意**不假裝成功**：否則你會以為鮑率換好了，然後對著還是亂碼的畫面查半天。
持有者離線後寫入權會自動交棒。若還沒登入（沒輸入連線密碼），畫面會說
「**請先在終端輸入連線密碼完成登入**」。

> 🔒 **這些設定不會被記住。** 面板上填的值只存在這個分頁的記憶體裡，
> 關掉頁面就消失，也不會寫進瀏覽器儲存（見下方「安全性」）。
> 記住上次的鮑率等於在這個公開網站上留下「你連的是什麼設備」的線索，
> 而省下的只是一次點選 —— 不值得。
>
> 改的是**這台 AirTTY 序列埠**的參數，不是你連著的設備本身；
> 而且只在本次連線有效，斷線後回到裝置的預設值。

## ⚠️ 必須從 HTTPS 或 localhost 開啟

Web Bluetooth 規格要求 **secure context**：頁面必須來自 `https://` 或 `http://localhost`，
否則瀏覽器根本不會提供藍牙 API（畫面會顯示「此頁必須經 HTTPS 或 http://localhost 開啟」）。

這個限制綁的是**網頁本身的來源**，與裝置無關（藍牙走空中，不經過網路），
所以裝置端**不需要**支援 HTTPS。

用上面的官方網址開啟就已經是 HTTPS，正常情況不必理會這條。
但如果你把檔案下載到本機、直接用 `file://` 雙擊開啟，**會不能用** —— 請改用下面的自架方法。

## 📲 加到主畫面（手機最推薦：一次設定，之後離線也能開）

本頁是 **PWA**，用手機瀏覽器開啟後可以「加到主畫面」，之後就像一般 App 一樣點圖示啟動，
**而且機房沒有網路也打得開**。

- **iPhone／iPad（Safari）**：分享鈕 → 「加入主畫面」。
  ⚠️ iOS 的 Web Bluetooth 需搭配支援的瀏覽器（見上方「瀏覽器支援」）。
- **Android（Chrome）**：右上角選單 → 「安裝應用程式」或「加到主畫面」。
- **桌機（Chrome／Edge）**：網址列右側的安裝圖示。

**為什麼離線還能用藍牙？** 藍牙走空中、本來就不需要網路；真正的障礙是
「網頁必須來自 HTTPS」（見上一節）。加到主畫面後，整包程式被存在你的裝置裡，
**而且仍然算是原本那個 HTTPS 網站**，所以藍牙功能照常可用。

> 💡 **請在還有網路的時候先開一次**（例如出發前、或在辦公室），讓它把程式存起來。
> 沒開過就直接進機房，等於什麼都沒存。
>
> 有新版本時，畫面下方會出現「↻ 有新版本 —— 點這裡重新整理套用」，點一下即可更新。

## 離線自架（備援：不想裝、或要給多台電腦用時）

機房常常是沒有對外網路的。**建議事先把這個目錄抓下來放在筆電裡**，需要時本機起一個
HTTP 伺服器就能用，完全不依賴網際網路。

**步驟：**

1. 下載本目錄的四個必要檔案（`index.html`、`app.js`、`xterm.js`、`xterm.css`），
   放進同一個資料夾。整個 repo 直接 `git clone` 或下載 ZIP 也可以（建議這樣做，
   會一併帶到 `sw.js` 與 `manifest.webmanifest`／圖示 —— 那幾個檔案讓自架的版本
   也能「加到主畫面」與離線開啟；少了它們核心的終端功能一樣完整，只是沒有 PWA 能力）。
2. 在該資料夾開啟終端機，執行：

   ```
   python3 -m http.server 8666
   ```

   （Windows 若沒有 `python3`，改打 `python -m http.server 8666`。）
3. 瀏覽器開 **`http://localhost:8666`** —— `localhost` 屬於 secure context，藍牙功能正常。
4. 用完按 `Ctrl+C` 關掉伺服器即可。

⚠️ 一定要用 `localhost`，**不要**改用本機 IP（例如 `http://192.168.x.x:8666`）——
那不算 secure context，藍牙 API 會消失。

也可以自行放上任何靜態 HTTPS 空間（GitHub Pages、自家網域皆可）：
單一資料夾、沒有 build 步驟、沒有後端。

## 安全性

console 流量（**包含你輸入的連線密碼**）全程流經這個頁面的 JavaScript，
而且本頁是**公開託管、給所有人使用**的工具，所以界線刻意畫得比一般網頁嚴格。

### 三條鐵律

- **零使用者資料持久化** —— 終端輸出、側錄、你打的指令、AI 問答內容，
  一律只存在**這個分頁的記憶體**裡，**關掉頁面就消失**。
  本站不會、也做不到把你的任何內容存下來：沒有後端、沒有資料庫、沒有帳號，
  程式裡也沒有任何一行把使用者內容寫進瀏覽器儲存。
  唯二的兩筆瀏覽器儲存是**字級**與**快捷鍵列展開狀態**兩個介面偏好
  （值只有一個數字與 `0`／`1`），詳見下方「本站在你瀏覽器裡放了什麼」。
- **零對外傳輸** —— 你打的每一個字只會經由藍牙送到手上那台裝置。
  頁面程式（`index.html` / `app.js`）**沒有任何一行對外的網路呼叫**；
  AI 排障功能刻意做成「複製到剪貼簿 + 幫你開官方聊天頁的分頁」，
  內容由**你自己貼上、自己按送出**，本站不代送、不看、也不存 API key。
- **零外部資源** —— `xterm.js` 與 `xterm.css` 就放在同一個資料夾，不引用任何 CDN，
  也沒有任何分析、追蹤、字型或廣告的第三方載入。
  因為完全不依賴外部資源，**離線自架的版本與線上版功能完全相同**。

### 可自行驗證（含唯一的例外，如實列出）

在本目錄執行：

```
grep -riE "fetch\(|XMLHttpRequest|WebSocket|sendBeacon|src=\"http" .
```

**預期命中就只有下面這張表列的項目** —— 行號會隨文件編修而變動，所以這裡列的是
「哪個檔案、幾筆、為什麼」，你可以逐檔對照：

| 檔案 | 命中數 | 是什麼 | 算不算對外傳輸 |
| --- | --- | --- | --- |
| `README.md` | 4 | 上面那道 grep 指令本身（1 筆），加上本表與下段解說裡引述 `sw.js` 那行程式的三處（3 筆） | ❌ 說明文字，不是程式 |
| `sw.js` | 1 | 離線快取的 `fetch(req)` | ❌ **只對本站自己的檔案**，見下方說明 |
| `app.js` / `index.html` / `xterm.js` / `CHANGELOG.md` | **0** | — | — |

> ⚠️ **關於 `sw.js` 那一筆，我們選擇講清楚而不是把它藏起來。**
> Service Worker 是「讓機房沒外網也能開這個頁面」的唯一手段（Web Bluetooth 只在
> HTTPS 下可用，快取住的頁面才保得住 HTTPS 身分）。它攔截網頁自己的檔案請求，
> 攔到之後要嘛給快取、要嘛跟本站要一份新的 —— 那一行 `fetch(req)` 就是後者。
> 它的上一行寫著 `if (url.origin !== self.location.origin) return;`：
> **凡是不屬於本站的網址，Service Worker 一律不碰**。
> 也就是說它只會去拿 `index.html`、`app.js`、`xterm.js` 這些你已經下載過的檔案，
> **不會、也沒有能力把你的 console 內容送到任何地方** ——
> 它從頭到尾沒有讀過側錄緩衝，`fetch(req)` 的 `req` 是瀏覽器給它的資源請求，
> 不含任何頁面資料。離線自架時它同樣只對你自己的伺服器作用。

## 已知行為與疑難排解

| 現象 | 說明／處理 |
| --- | --- |
| 裝置清單顯示「**無名裝置**」（Unknown or Unsupported Device） | **韌體 v1.7 起，清單會直接顯示 `AirTTY-A1-xxxx`**（找 `AirTTY-` 開頭的裝置即可）。**較舊韌體**顯示無名裝置是**正常**的 —— 舊版 BLE 廣播封包放不下裝置名稱；選擇視窗只列出提供 **Nordic UART 服務**的裝置，所以列出來的就是你的機器，多台並存時靠近一點依訊號強度判斷，連過一次之後清單才會顯示名稱 |
| 掃不到任何裝置 | ① 確認裝置端的藍牙開關已啟用、狀態為「廣播中」② **人數已滿時裝置會停止廣播**（韌體 v1.7 起最多兩人；較舊韌體一人），這時掃不到是**刻意設計**，請等其中一人離線 ③ Android 掃描 BLE **強制需要位置權限**（Android 12 以上允許「附近的裝置」；Android 11 以下要允許「位置」**並開啟系統定位服務**），只開藍牙一定掃不到 |
| 掃得到但連不上 | 連線人數已滿：**韌體 v1.7 起最多兩人同時連線**、**較舊韌體只允許一人**。也可能是距離太遠或裝置未開機 |
| 兩人連著，其中一人打不了字 | **正常**。兩人同看同一畫面，但**同時只有一人有輸入權**（先連上的人持有；他離線後另一人自動接手）。⚠️ 唯讀的人**無法主動接管** —— 韌體 v1.8 起藍牙有了控制通道（可換鮑率、送 Break），但**接管沒有做在裡面**：搶別人正在操作的 console 風險太高，只留在管理介面。要拿輸入權請改用管理介面的網頁終端，或等持有者離線 |
| Windows 第一次連線失敗 | 已知現象，本頁內建自動重試 ×3。若仍失敗，關掉分頁重開再試一次 |
| 連線中途斷掉 | 頁面會出現「重新連線」按鈕，按一下即可接回**同一台**裝置（不會跳出選擇視窗、不會連錯機器） |
| 沒有跳出裝置選擇視窗 | 瀏覽器的安全規定：一定要由你親自按下按鈕、親自點選裝置，網頁不能自己連。若按了沒反應，多半是瀏覽器不支援（見上方支援表） |
| 輸入密碼時畫面沒有回顯 | **正常**，密碼不會顯示星號，直接打完按 Enter |
| 停在 `Password:` 一陣子就被斷線 | 裝置端的防佔位保護；重連並儘快輸入密碼 |
| 手機上一行字被切掉、要左右滑 | 裝置端假設 80 欄，本頁不改欄數（改了裝置送來的換行位置會對不上）。請用 **A−** 縮小字級把 80 欄塞進畫面 |
| 看不到 **Break** 與 **⚙ 線路**按鈕 | 裝置韌體比 v1.8 舊，沒有控制通道 —— 屬預期行為（刻意隱藏而不是留假按鈕）。改用管理介面的網頁終端，或用 RFC 2217 軟體連 `<裝置 IP>:4001`（見上方「Break 鍵與線路控制」） |
| **Break** 按鈕在、但按了說「請先完成登入」 | 控制通道要等連線密碼登入完成才會就緒。先在終端輸入密碼，看到提示消失再按 |
| 換鮑率／Break 說「送出了但沒有生效」 | 你目前是**唯讀**（別人先連上、持有寫入權）。等對方離線自動交棒，或請對方讓出。見上方「按了卻說沒生效」 |
| 按快捷鍵完全沒反應 | 本頁**早期版本**有過這個問題（為了保住軟體鍵盤而攔截 `mousedown`，導致行動瀏覽器不觸發 `click`），現已修正。請**強制重新整理**頁面（Android Chrome：選單 →「重新載入」；或清掉網站資料）確保拿到新版 —— 這與**裝置韌體版本無關**，本頁是獨立更新的網頁 |
| 按「貼上」沒反應／跳出權限詢問 | 瀏覽器的剪貼簿權限。允許即可；若瀏覽器不給，改用終端本身的貼上（桌機 `Ctrl+Shift+V` 或按右鍵） |
| 按了快捷鍵之後手機軟體鍵盤收起來 | 不該發生（按鈕刻意不搶焦點）。若真的遇到，點一下終端畫面即可叫回鍵盤，並到下一節說的 GitHub Issues 回報 |

## 遇到問題怎麼回報

上一節沒對到症狀、或照做了還是不行，請開一張 GitHub Issue：

👉 **<https://github.com/AirTTY/airtty.github.io/issues>**（需要 GitHub 帳號，免費註冊）

點 **New issue** 會有兩種範本可選，照著填就不會漏東西：

| 範本 | 什麼時候用 |
| --- | --- |
| **網頁藍牙終端（webterm）問題** | 這個網頁本身的毛病：連不上、按鈕沒反應、畫面跑版、離線打不開 |
| **裝置本體問題** | AirTTY 機器的毛病：管理介面、Telnet／SSH、序列埠、燈號、電池、藍牙服務 |

### 請附上這幾項（缺了會來回問很久）

- **本頁版本** —— 看畫面**上方說明區的最後一行**，例如 `webterm v6`。
  ⚠️ 這一項很關鍵：本頁會離線快取，**你手上跑的常常不是伺服器上最新的那一版**。
  如果那裡顯示 `—`，照實寫「顯示 —」。
- **手機／電腦與瀏覽器版本** —— 例如「Pixel 7、Android 14、Chrome 126」。
- **怎麼開的** —— 從主畫面圖示啟動，還是在瀏覽器裡開網址。
  （兩者拿到的快取版本可能不同，這一項常常就是原因。）
- **裝置韌體版本** —— 管理介面**儀表板頁首**看得到，或用 SSH／裝置 Shell 讀
  `/etc/airtty/version`。不確定就寫「不確定」，不要用猜的。
- **重現步驟** —— 你按了什麼、順序如何，寫成一步一行。
- **預期是什麼、實際變成什麼**。
- **截圖**（有的話最好）。

> 🔒 **截圖或貼文字之前，請先遮掉：連線密碼、管理密碼、WiFi 密碼、內網 IP 與 MAC 位址、
> 設備主機名稱與 SNMP community。** Issue 是**公開**的，任何人都看得到，
> 而且改過之後編輯紀錄仍可能留存 —— 一旦貼出去很難真正收回。
>
> 💡 貼終端輸出時，用本頁的 **📄 維運報告**（勾「遮蔽敏感資訊」）產出的內容比較安全：
> 它會把 IP 只留前兩節、MAC 只留 OUI，`password`／`secret`／`community` 的值換成 `****`。
> 即使如此，送出前仍請自己再看過一遍。

**不必回報的情況**（這些是已知的預期行為，上一節與說明文件都有交代）：
Safari／iPhone 開不了、舊韌體上看不到 **Break**／**⚙ 線路**按鈕、
裝置在舊韌體上顯示為無名裝置、兩人同看時其中一人不能打字（含線路設定「沒有生效」）、
連線人數滿了掃不到裝置。

## 檔案

| 檔案 | 說明 | 授權 |
| --- | --- | --- |
| `index.html` | 版面、快捷鍵列（送出的位元組寫在按鈕的 `data-seq`，便於稽核）與自包含深色樣式 | MIT |
| `app.js` | Web Bluetooth 連線邏輯、快捷鍵、貼上、字級、側錄，以及 🔎 Log 檢視器／搜尋定位／⏱ 時間軸回放／📄 維運報告／廠牌智慧快捷鈕／亂碼偵測／🤖 AI 排障（官方聊天頁模式） | MIT |
| `xterm.js` / `xterm.css` | 終端機模擬函式庫（[xterm.js](https://github.com/xtermjs/xterm.js)） | MIT（第三方） |
| `sw.js` | Service Worker：離線快取（讓機房沒網路也能開）；`CACHE_VERSION` 就是頁面顯示的版本號 | MIT |
| `manifest.webmanifest` / `icon-*.png` | PWA 描述檔與圖示（加到主畫面用） | MIT |
| `CHANGELOG.md` | 變更紀錄，以 `CACHE_VERSION` 為鍵倒序。⚠️ **刻意不列入 `sw.js` 的 `SHELL`** —— 頁面不載它，連結指向 GitHub 上的檔案；列進去只會讓每個離線安裝多背一份純文字 | MIT |

> 🛠 **維護者請注意**：改動本目錄**任何檔案**後，必須把 `sw.js` 裡的 `CACHE_VERSION` 加一。
> 忘了加的下場是：使用者的瀏覽器永遠拿快取裡的舊版，你修好的 bug 到不了他手上，
> 而且從伺服器端完全看不出來（你看到的是新版，他看到的是舊版）。
> **加一的單位是「每一次上線」，不是「每一個分支或任務」** —— 同一個分支分兩波推，
> 第二波也要再加一次（2026-09-05 差一步踩過：第二波的改動一個使用者都拿不到）。
> 推之前的機械檢查：`git diff <上次上線的 commit>..HEAD -- webterm/ --stat`
> 有任何非 Markdown 檔的改動，`CACHE_VERSION` 就必須與線上值不同。
> 加一的同時要在 `CHANGELOG.md` 補一段 —— 頁面上的「看看改了什麼」連到那裡。
>
> 新增檔案時還要同步 `sw.js` 的 `SHELL` 清單 —— `addAll()` 是全有全無，
> 漏列或列錯任一個檔案，結果是**完全沒有離線能力**，而且不會有明顯的錯誤畫面。
> （唯一刻意不進 `SHELL` 的是 `CHANGELOG.md`：頁面不載它。）

> 🧪 **開發期怎麼測 Log 檢視器／回放／報告／AI（不必有硬體）**：
> 這幾個功能只吃「已經收到的位元組」，所以不需要真的連上裝置。
> `app.js` 是一般的 `<script>`（非 module），最外層的函式都在 `window` 上，
> 直接在瀏覽器 DevTools 的 Console 打就能灌假資料：
>
> ```js
> const u8 = new TextEncoder().encode('Switch# show version\r\n%LINK-3-UPDOWN: Gi0/2 down\r\n');
> term.write(u8);            // 畫到終端
> logAppend(u8);             // 進側錄
> logAppend(u8, Date.now() - 5000);   // 第二參數 = 自訂到達時間戳，測回放節奏用
> ```
>
> `logAppend` 的第二個參數 `t` **只存在於這條路徑**：正式流程（BLE 通知）一律不帶它，
> 由函式自己取現在時間。頁面上**沒有任何 UI、網址參數或熱鍵可以觸發它** ——
> 它不是隱藏的開發頁，也沒有多出任何檔案要進 `SHELL`，正式站上唯一打得到它的方式
> 就是使用者自己打開 DevTools 手動呼叫（那本來就等同於他自己在自己的瀏覽器裡貼字）。
