# AirTTY 網頁藍牙終端

**免安裝、免配對的瀏覽器 BLE 終端。**

👉 **[開啟網頁終端](https://airtty.github.io/webterm/)**

開頁 → 按「選擇裝置並連線」→ 從瀏覽器跳出的清單選你的 AirTTY → 輸入連線密碼 → 進 console。
不必切換 WiFi、不必安裝任何軟體、不必在系統裡先配對藍牙。

適合的情境：筆電正連著公司網路要一邊查資料、現場 WiFi 訊號很吵、或單純懶得換網路。

**手機也能好好操作** —— 內建快捷鍵列補上手機沒有的 Tab／Esc／Ctrl／方向鍵，
另有貼上、字級調整與連線紀錄下載。詳見下方「[快捷鍵列與工具列](#快捷鍵列與工具列)」。

## 瀏覽器支援

本頁使用 **Web Bluetooth**，支援情況如下：

| 平台 | 瀏覽器 | 支援 |
| --- | --- | --- |
| Windows | Chrome / Edge | ✅ |
| macOS | Chrome / Edge | ✅ |
| Android | Chrome / Edge | ✅（需允許「附近的裝置」權限） |
| Linux | Chrome | ✅ |
| 任何平台 | **Safari** | ❌ Safari 不支援 Web Bluetooth |
| iPhone / iPad | 任何瀏覽器 | ❌ iOS 一律用 Safari 引擎 → **請改用[使用手冊](../docs/manual-a1.md) §5.4 介紹的 App** |

其他連線方式（網頁終端、Telnet、傳統藍牙 SPP）不受此限制，見[使用手冊](../docs/manual-a1.md)。

## 快捷鍵列與工具列

手機沒有 Tab／Esc／Ctrl／方向鍵 —— 這是在行動裝置上操作 console 最大的痛點。
按標題列右側的 **⌨ 快捷鍵** 可展開／收合這排按鈕
（**手機預設展開**、桌機預設收起，你按過之後就記住你的選擇）。

### 按鍵（每一顆都是按一下就送出）

| 按鈕 | 送出（16 進位） | 用途 |
| --- | --- | --- |
| `Tab` | `09` | 指令補全 —— 網管最常按的一顆 |
| `Esc` | `1B` | 離開目前的提示／選單 |
| `?` | `3F` | Cisco 式的情境說明（context help） |
| `⏎` | `0D` | Enter（CR） |
| `Ctrl+C` | `03` | 中斷目前指令 |
| `Ctrl+Z` | `1A` | 回到特權模式／暫停前景工作 |
| `Ctrl+^` | `1E` | 即 **Ctrl+Shift+6** —— Cisco 用來中斷 `ping`／`traceroute`／`telnet` |
| `Ctrl+A` | `01` | 游標移到行首 |
| `Ctrl+D` | `04` | 刪除游標處字元／結束輸入（EOF） |
| `Ctrl+U` | `15` | 清掉整行重打 |
| `Ctrl+W` | `17` | 刪掉前一個單字 |
| `↑` | `1B 5B 41` | 上一筆歷史指令 |
| `↓` | `1B 5B 42` | 下一筆歷史指令 |
| `←` | `1B 5B 44` | 游標左移 |
| `→` | `1B 5B 43` | 游標右移 |
| `Break` | — | **目前無法使用**，見下方「Break 鍵」 |
| `Ctrl+…` | （不送位元組） | 進階備援，見下方 |

方向鍵送的是標準 CSI 序列（`ESC [ A/B/C/D`），Cisco IOS、Juniper Junos、Linux
的 readline 都吃這一組。`Ctrl+A`／`Ctrl+U`／`Ctrl+W` 是 console 行編輯最常用的三顆，
Cisco IOS、Junos 與 bash readline 通用。

**按鈕不會因為未連線而變成按不動** —— 未連線時按下去會跳出「尚未連線」提示浮條，
而不是靜靜地沒反應（分不出是「沒點到」還是「沒連線」很惱人）。每次點擊都有按壓閃爍回饋。

### Ctrl+…：進階備援（罕用組合才需要）

常用組合上表都給了獨立按鈕，正常操作用不到這顆。要送出上表沒有的組合
（例如 `Ctrl+X`、`Ctrl+R`）時：

1. 按一下快捷鍵列**最後一顆** **Ctrl+…** —— 按鈕變橘色並跳出「請再敲一個鍵」。
2. 從鍵盤（手機就是軟體鍵盤）敲下要組合的那個字元。
3. 該字元會以 Ctrl 組合送出，狀態自動解除。

對照規則是 ASCII 的標準做法（把字元碼的高位清掉，`& 0x1F`），另外補上幾個常用的：

| 你敲的鍵 | 實際送出 | | 你敲的鍵 | 實際送出 |
| --- | --- | --- | --- | --- |
| `A`–`Z`（大小寫皆可） | `01`–`1A` | | `?` | `7F`（DEL） |
| `[` `\` `]` `^` `_` | `1B`–`1F` | | 空白 或 `2` | `00`（NUL） |
| `6` | `1E`（同 `Ctrl+^`） | | `3` `4` `5` `7` | `1B` `1C` `1D` `1F` |

- 再按一次 **Ctrl+…** 可以取消等待。
- 等待中若改按其他直點按鍵（例如 Tab），該鍵會照原樣送出，Ctrl 等待狀態同時解除。

### Break 鍵（目前無法使用）

serial break 是**線路狀態訊號**（把 TX 線拉低超過一個字元時間），**不是一個字元**，
所以沒辦法「送某幾個位元組」達成。裝置端目前的藍牙通道是純資料流、
沒有頻外指令機制，因此這顆按鈕變暗；按下去會跳出說明，而不是做成按了沒反應的假按鈕。

**現在要送 Break，改用這兩條路**（兩者都走 RFC 2217 telnet 子協商，裝置端已支援）：

- 連上 AirTTY 的 WiFi → 開管理介面的**網頁終端**，那裡有 Break 按鈕。
- 用支援 **RFC 2217** 的軟體（PuTTY 的 telnet com-port、pyserial 的 `rfc2217://`、
  各家 VSP 虛擬序列埠工具）連 `<裝置 IP>:4001`。

### 其他工具

| 按鈕 | 說明 |
| --- | --- |
| **📋 貼上** | 讀剪貼簿內容送到裝置。**多行會先跳確認**，告訴你「即將送出 N 行、共幾個位元組」並顯示第一行 —— 誤貼整頁設定到正式設備是會出事的，這道確認就是為此而設。換行一律轉成 CR（終端的 Enter），不會多送空行。首次使用時瀏覽器會問剪貼簿權限 |
| **A− / A+** | 調整終端字級（8–24），會記住。**手機上請用它來讓 80 欄塞進畫面** —— 序列 console 不會協商視窗寬度，裝置端多半假設 80 欄，所以本頁固定 80 欄、只用字級調寬度（列數會自動填滿畫面高度） |
| **⬇ 下載紀錄** | 把這次連線收到的畫面輸出存成 `.txt`。檔名含裝置名與時間（例如 `AirTTY-A1-1a2b-20260818-143302.txt`）。**只記錄裝置送來的輸出，不記錄你按的鍵，所以連線密碼不會進紀錄**。內容已移除終端控制碼；緩衝上限 2 MB，超過時保留最新的部分。斷線後仍可下載 |

## ⚠️ 必須從 HTTPS 或 localhost 開啟

Web Bluetooth 規格要求 **secure context**：頁面必須來自 `https://` 或 `http://localhost`，
否則瀏覽器根本不會提供藍牙 API（畫面會顯示「此頁必須經 HTTPS 或 http://localhost 開啟」）。

這個限制綁的是**網頁本身的來源**，與裝置無關（藍牙走空中，不經過網路），
所以裝置端**不需要**支援 HTTPS。

用上面的官方網址開啟就已經是 HTTPS，正常情況不必理會這條。
但如果你把檔案下載到本機、直接用 `file://` 雙擊開啟，**會不能用** —— 請改用下面的自架方法。

## 📲 加到主畫面（手機最推薦：一次設定，之後離線也能開）

本頁是 **PWA**，用手機瀏覽器開啟後可以「加到主畫面」，之後就像一般 App 一樣點圖示啟動，
**而且機房沒有網路也打得開**。

- **iPhone／iPad（Safari）**：分享鈕 → 「加入主畫面」。
  ⚠️ iOS 的 Web Bluetooth 需搭配支援的瀏覽器（見上方「瀏覽器支援」）。
- **Android（Chrome）**：右上角選單 → 「安裝應用程式」或「加到主畫面」。
- **桌機（Chrome／Edge）**：網址列右側的安裝圖示。

**為什麼離線還能用藍牙？** 藍牙走空中、本來就不需要網路；真正的障礙是
「網頁必須來自 HTTPS」（見上一節）。加到主畫面後，整包程式被存在你的裝置裡，
**而且仍然算是原本那個 HTTPS 網站**，所以藍牙功能照常可用。

> 💡 **請在還有網路的時候先開一次**（例如出發前、或在辦公室），讓它把程式存起來。
> 沒開過就直接進機房，等於什麼都沒存。
>
> 有新版本時，畫面下方會出現「↻ 有新版本 —— 點這裡重新整理套用」，點一下即可更新。

## 離線自架（備援：不想裝、或要給多台電腦用時）

機房常常是沒有對外網路的。**建議事先把這個目錄抓下來放在筆電裡**，需要時本機起一個
HTTP 伺服器就能用，完全不依賴網際網路。

**步驟：**

1. 下載本目錄的四個檔案（`index.html`、`app.js`、`xterm.js`、`xterm.css`），
   放進同一個資料夾。整個 repo 直接 `git clone` 或下載 ZIP 也可以。
2. 在該資料夾開啟終端機，執行：

   ```
   python3 -m http.server 8666
   ```

   （Windows 若沒有 `python3`，改打 `python -m http.server 8666`。）
3. 瀏覽器開 **`http://localhost:8666`** —— `localhost` 屬於 secure context，藍牙功能正常。
4. 用完按 `Ctrl+C` 關掉伺服器即可。

⚠️ 一定要用 `localhost`，**不要**改用本機 IP（例如 `http://192.168.x.x:8666`）——
那不算 secure context，藍牙 API 會消失。

也可以自行放上任何靜態 HTTPS 空間（GitHub Pages、自家網域皆可）：
單一資料夾、沒有 build 步驟、沒有後端。

## 安全性

console 流量（**包含你輸入的連線密碼**）全程流經這個頁面的 JavaScript，
所以本頁刻意做成可稽核、可自行託管：

- **零對外傳輸** —— 全檔沒有 `fetch` / `XMLHttpRequest` / `WebSocket` / `sendBeacon`，
  你打的每一個字只會經由藍牙送到手上那台裝置。
- **零外部資源** —— `xterm.js` 與 `xterm.css` 就放在同一個資料夾，不引用任何 CDN。
- **可自行驗證** —— 在本目錄執行下列指令，唯一的命中應該只有這段說明文字自己
  （本檔與 `app.js` 的註解），程式碼本體零命中：

  ```
  grep -riE "fetch\(|XMLHttpRequest|WebSocket|sendBeacon|src=\"http" .
  ```

- **紀錄與剪貼簿也留在本機** —— 「⬇ 下載紀錄」用瀏覽器的 `Blob` 在你的裝置上直接產生檔案，
  「📋 貼上」用的 `navigator.clipboard` 也只在頁面內作業，兩者都不會產生任何網路請求。
  連線紀錄只收裝置端送出的輸出、不收你按的鍵，**因此連線密碼不會出現在紀錄檔裡**。
- 因為完全不依賴外部資源，**離線自架的版本與線上版功能完全相同**。

## 已知行為與疑難排解

| 現象 | 說明／處理 |
| --- | --- |
| 裝置清單顯示「**無名裝置**」（Unknown or Unsupported Device） | **韌體 v1.7 起，清單會直接顯示 `AirTTY-A1-xxxx`**（找 `AirTTY-` 開頭的裝置即可）。**較舊韌體**顯示無名裝置是**正常**的 —— 舊版 BLE 廣播封包放不下裝置名稱；選擇視窗只列出提供 **Nordic UART 服務**的裝置，所以列出來的就是你的機器，多台並存時靠近一點依訊號強度判斷，連過一次之後清單才會顯示名稱 |
| 掃不到任何裝置 | ① 確認裝置端的藍牙開關已啟用、狀態為「廣播中」② Android 掃描 BLE **強制需要位置權限**（Android 12 以上允許「附近的裝置」；Android 11 以下要允許「位置」**並開啟系統定位服務**），只開藍牙一定掃不到 |
| 掃得到但連不上 | **BLE 一次只允許一條連線**。請確認沒有其他手機／電腦正連著同一台裝置 |
| Windows 第一次連線失敗 | 已知現象，本頁內建自動重試 ×3。若仍失敗，關掉分頁重開再試一次 |
| 連線中途斷掉 | 頁面會出現「重新連線」按鈕，按一下即可接回**同一台**裝置（不會跳出選擇視窗、不會連錯機器） |
| 沒有跳出裝置選擇視窗 | 瀏覽器的安全規定：一定要由你親自按下按鈕、親自點選裝置，網頁不能自己連。若按了沒反應，多半是瀏覽器不支援（見上方支援表） |
| 輸入密碼時畫面沒有回顯 | **正常**，密碼不會顯示星號，直接打完按 Enter |
| 停在 `Password:` 一陣子就被斷線 | 裝置端的防佔位保護；重連並儘快輸入密碼 |
| 手機上一行字被切掉、要左右滑 | 裝置端假設 80 欄，本頁不改欄數（改了裝置送來的換行位置會對不上）。請用 **A−** 縮小字級把 80 欄塞進畫面 |
| **Break** 按鈕是暗的、按了只跳說明 | 目前藍牙通道做不到 serial break，屬預期行為。改用管理介面的網頁終端，或用 RFC 2217 軟體連 `<裝置 IP>:4001`（見上方「Break 鍵」） |
| 按快捷鍵完全沒反應 | 本頁**早期版本**有過這個問題（為了保住軟體鍵盤而攔截 `mousedown`，導致行動瀏覽器不觸發 `click`），現已修正。請**強制重新整理**頁面（Android Chrome：選單 →「重新載入」；或清掉網站資料）確保拿到新版 —— 這與**裝置韌體版本無關**，本頁是獨立更新的網頁 |
| 按「貼上」沒反應／跳出權限詢問 | 瀏覽器的剪貼簿權限。允許即可；若瀏覽器不給，改用終端本身的貼上（桌機 `Ctrl+Shift+V` 或按右鍵） |
| 按了快捷鍵之後手機軟體鍵盤收起來 | 不該發生（按鈕刻意不搶焦點）。若真的遇到，點一下終端畫面即可叫回鍵盤，並回報給我們 |
